# MCHOSE 无线鼠标 HID 协议笔记

设备：MCHOSE A7 V3 Ultra+，接收器 `VID 0x3837 / PID 0x1018`，另有充电底座 `MagDock 0x1012`。

## 接口

接收器是一个 4 接口复合 HID 设备：

| 接口 | Usage Page/Usage | 报告长度 | 说明 |
|---|---|---|---|
| `MI_00` | `0x0001/0x0002` | — | 鼠标集合，**普通进程打不开**（Windows 与浏览器都禁止） |
| `MI_01 Col01` | `0x0001/0x0006` | — | 键盘集合，同样禁止打开 |
| `MI_01 Col02` | `0x000C/0x0001` | 3/1/1 | 多媒体键 |
| `MI_02 Col01` | `0xFF0B/0x00C4` | 61/61/61 | 读得到 caps，写入一律 `ERROR_INVALID_PARAMETER` |
| `MI_02 Col02` | `0xFF01/0x0001` | 64/64/64 | **配置通道**：报告 ID `0x4D`，63 字节负载 |
| `MagDock` | `0xFF00/0x0001` | 65/65 | 无有效响应 |

## 帧格式（接收器 ↔ 主机）

HID 报告 ID `0x4D`，负载 63 字节：

```
01 01 | <cmd> <sub> | <args...> | 00 ...
```

* `02 xx`：读请求。实测 `02 03` 有应答（返回设置包 `11 03`），其余 `02 00`–`02 31` 只回显。
* `11 xx`：设置包（双向）。
* `01 xx`：确认/应答包。
* `00 xx`：另一族读请求（`00 02` 返回 `13 02` 的 DPI 包）。

`11 03` 应答负载（偏移从负载第 0 字节算）：

```
00: 01 01
02: 11 03
04: 00 00 00 00 00
09: 06            ; DPI 档位数量
10: 03            ; 当前档位索引
11: 00
12: 90 01         ; 400
14: 20 03         ; 800
16: 40 06         ; 1600
18: 66 08         ; 2150
20: 00 19         ; 6400
22: 50 C3         ; 50000
```

数值均为小端 uint16。

## 电量

接收器在鼠标**重新连上**（开关键拨一下、接收器重新插拔）时主动推一包链路状态：

```
4D | 01 01 0D 00 06 00 00 02 00 00 47 00 00 00 00 00 00 00 00 00 4F 00 …
                  ^^                       ^^                       ^^
               命令 0x0D                 电量 0x47 = 71%            0x4F
```

* 命令 `0x0D` = 已连接，`0x0C` = 已断开（此时载荷第 2 字节变成 `00`）
* 电量在命令字节后第 8 个字节，实测 `0x47` 与驱动页面显示的 71% 一致
* `0x4F`（79）含义未知，疑似满电参考值，暂不采用
* 驱动前端另有 `command == 0x0A && type == 0x05` 的电量包（含 `fullStatus` / `chargeStatus` 半字节），
  但这台设备在我们的抓包里从未出现，充电状态暂时无法区分

**没有请求-应答式的「读电量」命令**：`02 06`（设备信息）在这款接收器上只回显不回答，
`02 00`–`02 31` 扫过一遍也只有 `02 03` 有应答（返回设置包）。所以电量只能被动等事件，
这也是官方页面只在你开关鼠标后更新电量的原因。

## 已知坑

* 键盘/鼠标顶层集合被系统拒绝（`ERROR_ACCESS_DENIED`），只能走厂商集合。
* `MI_02 Col01`（61 字节）完全不可写，别浪费时间去猜报告 ID。
* 接收器的输入报文是**回显 + 应答**混在一起：发什么，先回一份同样的；真正应答跟在后面或后续报文。
